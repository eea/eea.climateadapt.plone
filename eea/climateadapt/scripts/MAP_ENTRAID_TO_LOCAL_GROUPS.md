# Map EntraID Users to Local Groups Script

This script maps users from **Eionet LDAP group memberships** to corresponding **local Plone groups** (e.g. `extranet-cca-editors` → `local-cca-editors`) by searching for each user's Microsoft Entra ID account in Plone based on their email address.

---

## Rationale

Climate-ADAPT is migrating authentication from Eionet LDAP to **Microsoft Entra ID** (OAuth2 via `pas.plugins.authomatic` and `pas.plugins.eea`).

In Entra ID:
- Entra ID user IDs in Plone are UUIDs.
- Login names are set to the user's email address.
- Group memberships are **not automatically synced** from Azure AD to Plone.
- Authorization relies on local Plone groups (prefixed with `local-`) which receive local roles on content.

While `migrate_eionet_groups.py` previously updated local role permissions on content paths from `extranet-*` to `local-*`, this script solves the user membership side: ensuring that Entra ID users are placed into the corresponding `local-*` groups so they retain their permissions.

---

## Features

- **Dual Data Source Modes**:
  - **Live LDAP**: Directly queries Eionet LDAP (using `pasldap` settings in `acl_users`, identical to `export_eionet_groups.py`). Requires EEA VPN.
  - **Pre-exported CSV (`--eionet-csv`)**: Accepts the CSV generated by `export_eionet_groups.py` (e.g., `artifacts/eionet_ldap_groups.csv` or `eionet_groups.csv`). Ideal for running on staging or environments without direct LDAP connectivity!
- **Safe Dry-Run by Default**: Defaults to dry-run preview mode. Requires the `--run` flag to commit changes to the database.
- **Automatic Group Creation**: If a target `local-*` group does not exist in `portal_groups`, it is automatically created.
- **Idempotent**: Users already belonging to the target local group are detected and skipped (`ALREADY_MEMBER`).
- **Comprehensive User Resolution**:
  - Builds an in-memory index from `acl_users.authomatic` (`_useridentities_by_userid`) and `acl_users.mutable_properties` (`_storage`).
  - Fallback queries via `acl_users.searchUsers` and `portal_membership`.
  - Normalizes email addresses case-insensitively.
- **Detailed Reporting**:
  - Clear console table summary per group.
  - Optional machine-readable CSV export (`--csv <output.csv>`).

---

## Prerequisites

- **If querying LDAP directly**: EEA VPN connection must be active (`ldaps://ldap.eionet.europa.eu:636`).
- **If using `--eionet-csv`**: No VPN required; simply provide the path to the CSV exported from `export_eionet_groups.py`.
- **Target users in Plone**: Entra ID users must either:
  1. Have logged in at least once via Entra ID OAuth2, or
  2. Have been synchronized via `sync_eea_entra`.
  *(Users who haven't logged in or been synced will be reported as `USER_NOT_FOUND`)*.

## How to Run

### On Staging or Local Docker Stack

#### 1. Dry-Run using a pre-exported CSV (Recommended for Staging):

```bash
docker compose exec backend /app/docker-entrypoint.sh /app/bin/python3 \
    /app/sources/eea.climateadapt/eea/climateadapt/scripts/map_entraid_to_local_groups.py \
    --portal cca --zope-conf etc/relstorage.conf \
    --eionet-csv /app/sources/eea.climateadapt/data/eionet_ldap_groups.csv
```

#### 2. Dry-Run with Live LDAP (Requires EEA VPN):

```bash
docker compose exec backend /app/docker-entrypoint.sh /app/bin/python3 \
    /app/sources/eea.climateadapt/eea/climateadapt/scripts/map_entraid_to_local_groups.py \
    --portal cca --zope-conf etc/relstorage.conf
```

#### 3. Commit Changes to Database (`--run`):

```bash
docker compose exec backend /app/docker-entrypoint.sh /app/bin/python3 \
    /app/sources/eea.climateadapt/eea/climateadapt/scripts/map_entraid_to_local_groups.py \
    --portal cca --zope-conf etc/relstorage.conf \
    --eionet-csv /app/sources/eea.climateadapt/data/eionet_ldap_groups.csv \
    --run
```

#### 4. Export Detailed CSV Audit:

```bash
docker compose exec backend /app/docker-entrypoint.sh /app/bin/python3 \
    /app/sources/eea.climateadapt/eea/climateadapt/scripts/map_entraid_to_local_groups.py \
    --portal cca --zope-conf etc/relstorage.conf \
    --eionet-csv /app/sources/eea.climateadapt/data/eionet_ldap_groups.csv \
    --csv mapping_report.csv
```

### Using Makefile Targets

From the `backend/` directory:

```bash
# Dry run
make map-entraid-to-local-groups ARGS="--eionet-csv /path/to/eionet_groups.csv"

# Live run (commits changes)
make map-entraid-to-local-groups-run ARGS="--eionet-csv /path/to/eionet_groups.csv"
```

## Arguments

| Argument | Required | Default | Description |
|---|---|---|---|
| `--portal` | No | `cca` | Portal ID |
| `--zope-conf` | Yes | — | Path to Zope / RelStorage configuration file |
| `--run` | No | False | Commit changes to database (without this, runs in dry-run mode) |
| `--eionet-csv` | No | None | Path to CSV exported by `export_eionet_groups.py` |
| `--filter` | No | `extranet-cca*` | LDAP wildcard filter for groups when querying LDAP directly |
| `--group` | No | None | Process only a specific LDAP group (e.g. `extranet-cca-editors`) |
| `--prefix-from` | No | `extranet-` | Prefix in LDAP group name to replace |
| `--prefix-to` | No | `local-` | Replacement prefix for local group name |
| `--csv` | No | None | Path to export detailed CSV mapping report |
| `--verbose` | No | False | Enable verbose output (prints each user check) |

---

## Output Explanation

Each group member check results in one of the following statuses:

| Status | Meaning |
|---|---|
| `WOULD_ADD` | Dry-run mode: User found in Plone and would be added to the local group. |
| `ADDED` | Live run: User was successfully added to the local group. |
| `ALREADY_MEMBER` | User is already a member of the local group (idempotent, no action taken). |
| `USER_NOT_FOUND` | User's email from LDAP was not found in Plone. The user has not logged in via Entra ID yet or has not been synced via `sync_eea_entra`. |
| `NO_EMAIL` | LDAP entry has no email address; cannot correlate to an Entra ID account. |

## Troubleshooting

- **"Could not connect to Eionet LDAP server"**: The LDAP server (`ldap.eionet.europa.eu:636`) requires the EEA VPN. If running on staging without VPN, use `--eionet-csv <path>` with the pre-exported CSV instead.
- **Many `USER_NOT_FOUND` results**: This is expected if users have not yet logged into the staging/production site with Microsoft Entra ID. Once a user logs in (or after running `sync_eea_entra`), re-running this script will immediately detect and map them.
